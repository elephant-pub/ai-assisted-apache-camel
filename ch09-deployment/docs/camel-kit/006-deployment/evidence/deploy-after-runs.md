# Deploy lab after-runs — pipeline 006-deployment, wave 5 (2026-11-16)

The "after" column of design 006 §3.14 (second table): the same lab and scripts as the before-runs L0–L7
([`deploy-lab-runs.md`](deploy-lab-runs.md)), against the release. A run that misses its expectation is a finding
(plan P-17), not re-run until green.

## Setup

- **Cluster:** kind `trailhead-lab` (Kubernetes v1.34.0, one node, arm64), only through `deploy/local/kube.sh`.
- **Systems:** as in L0–L7 (`deploy/local/lab/k8s/systems.yaml`), unchanged, with their Secrets from
  `target/lab/secrets` (never committed). The design-phase "today" Deployment, its settings ConfigMap and Service were
  deleted before the first run, so the release is the only integration instance.
- **The release:** `deploy/local/lab/k8s/release` = `deploy/k8s/base` (StatefulSet, one replica, probes on 9090, 90 s
  grace, 1 GiB, restricted security context, NetworkPolicy, partner ConfigMap with content hash) in `trailhead-lab`,
  with the lab's settings, the image `trailhead/order-integration:006` (`sha256:7346a64c840e…`, `kind load`), and the
  lab-only truststore option for the lab mail server (as `deploy/k8s/ci`, W4-F2). Secrets from `deploy/ci/smoke.sh
  secrets` (`lab.sh smoke secrets`). Applied with `lab.sh app-sts deploy/local/lab/k8s/release`.
- **Load:** `lab.sh stream` (a Partner Order every 0.25 s from the client pod; order numbers outside the partner's range
  unless stated, so a served answer is the contract's 422 and `000` is no connection); `lab.sh events`.
- Raw outputs: [`runs-after/`](runs-after/). Times in the run files: `==` lines are the machine's local time
  (UTC−6), the stream and pod lines UTC.

## Findings (P-17)

- **W5-F3 (A2, measured value).** A rollout leaves partners without an answer for about 16 s (old pod stopping to new
  pod ready) plus up to curl's own limit for a request sent at the moment the old pod's network goes away (one request
  waited the full 15 s instead of being refused). The design's estimate was 10–15 s of refused connections (§3.1 T3,
  OQ-088). One pod (D4) is the cause, as designed; the number for OQ-088 is ~16–21 s in this lab.
- **W5-F5 (A6b, expectation not met).** With `-Xmx96m` (the plan's value) and in a supplementary run `-Xmx64m`, the L7
  burst did not exhaust the heap, so `-XX:+ExitOnOutOfMemoryError` (exit 3) was not seen in the lab; nothing was lost.
  The option is in the entrypoint (T2, A1). Proving exit 3 needs a load or heap that the lab burst does not reach (e.g.
  a much smaller heap, or a fault point that allocates); not run, to keep the after-runs as planned.
